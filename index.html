④ 加自己的游戏 & 判定区间

内置只有 4 款。想加别的游戏，就在这里写一段 JSON —— 格式是 { "游戏名": { "a0": 支持音频延迟, "a1": 支持判定延迟, "tiers": [档位…] } }。 每个档位可以写 name（名字）、role（center 正中 / near 近 / far 远 / miss 漏）、 dir（这一档结算里有没有早/晚）、ms（判定区间 ±毫秒，只用于记录和展示，不参与计算）。 自定义游戏存在这个浏览器里，换了设备不会跟着走。

⑤ 怎么测才准

  1. 先分型：跟着音乐打的（听押）调音频延迟；跟着画面判定线打的（目押）调判定延迟。只调一栏。
  2. 至少测 3 个轴值：比如 0 / +20 / +40，每个值打 2 局以上。同一个值打两局，是为了看波动。
  3. 确认设置真的生效了：改完数字要按确认、回主菜单再进曲目，不然下一局用的还是旧值。
  4. 两局差超过 3 个百分点：说明这局状态不稳，别急着下结论，再补一局。
  5. 看命中率和环带，不要盯着「早和晚一样多」—— 早押的人天生就偏早，「早」永远比「晚」多。

⑥ 关于这个工具

  • 算法：把「轴值 → 命中率」拟成抛物线，取顶点当建议值；因为波动大，顶点旁边还会给一个重采样算出来的区间，而不是一个精确到毫秒的数字。
  • 不联网：所有计算都在你的浏览器里，数据存在 localStorage，关掉网页也还在。
  • 会老实说「不够」：少于 3 个轴值、或者每组只有 1 局，它只会说「数据不够」，不会硬编一个数字出来。
  • 每个游戏自己声明档位：每款游戏的判定档位都标了角色（正中 / 近 / 远 / 漏），并且单独标明「这一档的结算里有没有早 / 晚」——所以有的游戏只填总数，有的能填细分，界面自动跟着变。
  • 主指标可选：如果一款游戏有「大P / 小P」两个正中档，可以选「只用最严档」还是「正中档合并」，两种都能算、都能切换。
