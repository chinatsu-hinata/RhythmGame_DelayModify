④ 加自己的游戏 & 判定区间

内置游戏不够用？在这里写一段 JSON 就能加。同名会覆盖内置那一款，所以连内置的也能改。 每款游戏声明：a0 支不支持音频延迟、a1 支不支持判定延迟、tiers 判定档位列表 （role 是 center / near / far / miss； fl 表示结算画面上有没有整局一对的 Fast / Late 计数 —— 标了它，表单才会出现那一对可选框； dir 表示这一档的数字里是否含着 Fast / Late（只是标记，不影响计算）； nest 表示这一档的数字包含上面（更窄）那几档：玩家照结算填原数字，程序自动做减法）， ms 是判定区间：写一个数 70 表示 ±70ms 对称，写一对 [-150, 200] 表示早侧 150ms、晚侧 200ms 的不对称窗口）。

⑤ 如何使用这个工具

  • I. 先在游戏列表里面选择游戏，看看有没有支持你的游戏
  • II. 先用你目前的延迟游玩一次游戏
  • III. 记录下Perfect,Great等的数量以及有多少个Fast/Late，并且在工具中输入
  • IV. 微调延迟(推荐±50ms)
  • V. 重复步骤II-IV，直到你有3个在不同延迟下打的成绩数据
  • VI. 看一下拟合出来的建议延迟，如果延迟波动过大或者希望得到更准确的延迟可以重复步骤II-IV
  • VII. 按照推荐的延迟游玩一局后再把数据输入到工具里作验算，如果这个延迟依旧落在区间里面就可以使用，否则请重复II-IV

⑥ 怎么测才准

  1. 先分型：听声音打的（音押）调「音频延迟」；看画面打的（目押）调「判定延迟」。
  2. 同一个设置建议打 2 局，一共测 3 个以上不同的轴值（比如 0 / -5 / +40）。
  3. 每次改完设置，记得按确认并回主菜单再进曲目 —— 否则测的还是旧值。
  4. 两个设置的结果如果只差 3 个百分点以内，说明这一局本身就不稳，再多打两局。
  5. 结论只给区间，不给"精确到 1ms"的假精度；区间内随便挑一个整数就行。

⑦ 关于这个工具

  • 算法：把每个轴值的「正中率」当数据点，用二次曲线拟合，取顶点作为建议值（夹在你测过的轴值范围内），建议区间 = 顶点 ± 半个最小刻度；再用 bootstrap 重采样估算重复性——同一批数据每次算出来完全一样，它只回答「重打一局这个数会晃多少」，不含「模型选错了」的误差。
  • 曲线不是抛物线：真实的命中率是「判定窗口 ⊗ 玩家误差分布」的卷积，顶部是平的。平顶区里拟合本来就分不清，所以结论请当区间用。
  • 不联网：所有计算都在你的浏览器里，数据存在 localStorage，关掉网页也还在。
  • 会老实说「不够」：少于 3 个轴值、或者每组只有 1 局，它只会说「数据不够」，不会硬编一个数字出来。
  • 每个游戏自己声明档位：每档都标了角色（正中 / 近 / 远 / 漏），并标明这一档的数字里含不含早 / 晚。
  • 主指标可选：有「大P / 小P」两个正中档的游戏，可以选「只用最严档」还是「正中档合并」。
