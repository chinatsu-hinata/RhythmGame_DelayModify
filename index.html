④ 加自己的游戏 & 判定区间

内置游戏不够用？在这里写一段 JSON 就能加。同名会覆盖内置那一款，所以连内置的也能改。 每款游戏声明：a0 支不支持音频延迟、a1 支不支持判定延迟、tiers 判定档位列表 （role 是 center / near / far / miss，dir 表示这一档结算里有没有早 / 晚， ms 是判定区间：写一个数 70 表示 ±70ms 对称，写一对 [-150, 200] 表示早侧 150ms、晚侧 200ms 的不对称窗口）。

⑤ 怎么测才准

  1. 先分型：听声音打的（听押）调「音频延迟」；看画面打的（目押）调「判定延迟」。
  2. 同一个设置至少打 2 局，一共测 3 个以上不同的轴值（比如 0 / +20 / +40）。
  3. 每次改完设置，记得按确认并回主菜单再进曲目 —— 否则测的还是旧值。
  4. 两个设置的结果如果只差 3 个百分点以内，说明这一局本身就不稳，再多打两局。
  5. 结论只给区间，不给"精确到 1ms"的假精度；区间内随便挑一个整数就行。

⑥ 关于这个工具

  • 算法：把每个轴值的「正中率」当数据点，用二次曲线拟合，取顶点作为建议值，再用 bootstrap 重采样给区间。
  • 不联网：所有计算都在你的浏览器里，数据存在 localStorage，关掉网页也还在。
  • 会老实说「不够」：少于 3 个轴值、或者每组只有 1 局，它只会说「数据不够」，不会硬编一个数字出来。
  • 每个游戏自己声明档位：每档都标了角色（正中 / 近 / 远 / 漏），并单独标明这一档有没有早 / 晚细分。
  • 主指标可选：有「大P / 小P」两个正中档的游戏，可以选「只用最严档」还是「正中档合并」。
